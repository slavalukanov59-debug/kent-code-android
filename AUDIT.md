# Технический аудит KENT CODE 0.5.3

База — `main` на `05983a74b601a00b1958ae712c9e3305a2a7c7da`. Тег `kent-build-44` указывает на тот же коммит. Последний запуск Actions на базе был успешным. На момент аудита PR № 1–15 закрыты, ветка `feature/kent-evolution-0.6` отсутствовала. Историю изучили от первого Android MVP до исправлений 0.5.3. [Базовый релиз](https://github.com/slavalukanov59-debug/kent-code-android/releases/tag/kent-build-44) · [Базовый запуск Actions](https://github.com/slavalukanov59-debug/kent-code-android/actions/runs/44530510572)

| Критичность | Компонент | Наблюдение в 0.5.3 и решение в 0.6 |
| --- | --- | --- |
| Критическая | `KentAgent`, `MainActivity` | AUTOPILOT возвращал согласие для любого запроса инструмента, включая shell, Termux и Shizuku. В 0.6 автоматизация ограничена подготовленной рабочей папкой приложения. Операции с shell выполняются по действию пользователя в разделе Termux. |
| Критическая | `SafeWorkspace` | Проверка секретов выполнялась по входному пути, а символическая ссылка могла подменить цель. Запрещены неоднозначные пути и символические ссылки. Запись сравнивает обработанную версию файла с содержимым, которое было показано перед подтверждением. |
| Высокая | `MissionStore`, `KentAgent` | Имя инструмента записывалось уже после выполнения. При завершении процесса запись могла измениться без сохранённого результата. Журнал теперь фиксирует намерение до изменения и исход после. Неопределённое действие требует сверки. |
| Высокая | `MainActivity`, фон Android | Хранилища создавались на экземпляр Activity. При пересоздании экрана новый экземпляр мог начать восстановление до завершения старого. Сейчас владелец хранилищ живёт в процессе, а активная задача при уходе в фон переходит к сохранению и паузе. |
| Высокая | `LocalTermuxBridge`, `TermuxBridge`, `ShellRunner` | Старый локальный протокол передавал токен как поле запроса и обрезал сериализованный JSON. Потеря ответа смешивалась с завершением команды. Добавлены взаимная HMAC-аутентификация, ограничение содержимого до кодирования ответа, раздельный код выхода и признак возможного продолжения процесса. Прямой результат принимает закрытый Android-приёмник. |
| Высокая | Chat Completions | Ошибка могла выводить текст сервера. Ответ и перенаправления были недостаточно строго ограничены. Теперь редиректы запрещены, используются категории ошибок, размер ответа ограничен, тело закрывается, а повтор 429 учитывает оплату и `Retry-After`. Таймаут POST оставляет задачу для проверки. |
| Высокая | `CreditBalance`, `TokenMeter` | AI-FLEX запрашивал недокументированный маршрут, а подбор произвольных числовых полей мог выдать расход за остаток. Версия 0.6 использует официальный сценарий `/v1/usage` и поле `remaining`. UI отражает доступность данных и подтверждённую стоимость OpenRouter. [AI-FLEX](https://ai-flex.online/docs?section=cmd-line&topic=cli-cc-switch-usage) · [OpenRouter](https://openrouter.ai/docs/guides/guides/usage-accounting) |
| Средняя | `ChatJournal`, чат | Чтение обеих JSONL-частей и построение всех карточек происходили при запуске. Повреждённый хвост мог поглотить следующую запись. Добавлены чтение с конца, стабильные IDs, восстановление последней строки и виртуализированный список. |
| Средняя | Модельный контекст и память | Старые задачи вытеснялись после 25 записей, исходное задание обрезалось, а 500 шагов ограничивали длинные задачи. Контекст выбирает цель, факты, последние связанные группы вызовов и точки восстановления. Выполнение останавливается при повторяющихся действиях без прогресса. Размеры I/O и хранилища имеют технические границы. |
| Средняя | GitHub | В 0.5.3 отсутствовали рабочие API-операции над репозиторием. Добавлены чтение, сравнение, Actions и ручное подтверждение веток, текстовых коммитов и черновиков PR. Коммит проверяет ожидаемый SHA, прямая правка ветки по умолчанию запрещена. |
| Средняя | `SecureKeyStore`, Manifest | Android Keystore AES-GCM и существующий формат шифротекста сохранены. Исправлена совместимость вызовов Java с min SDK, добавлены явные исключения резервного копирования и переноса данных, GitHub использует отдельный зашифрованный токен. |
| Низкая | Gradle, Actions и документы | Ранее CI выполнял smoke-тесты без полноценного Android lint/JUnit на этой ветке. Конфигурация 0.6 собирает APK и контрольную сумму, запускает lint и публикует артефакт запуска. Текущая инструкция отделена от исторической документации. |

Приложение построено на нативных Android Views, поэтому проверки WebView здесь неприменимы. Целей аудита по стабильности касаются активность и клавиатура, объём истории, состояние процесса, локальный I/O и сетевые ответы.

Границы подтверждения: единственный активный агент на процесс, движение в фон приводит к паузе, аппаратные разрешения подтверждаются реальным Android и Shizuku, а отчёт модели о проведённых тестах требует сверки с фактическим журналом. Принимаемый формат файлов для агента — текст UTF-8. Дистрибутив GitHub — debug APK с target SDK 35. Для будущей публикации в Google Play применяются требования к SDK на дату подачи. [Требования Google Play](https://developer.android.com/google/play/requirements/target-sdk)
