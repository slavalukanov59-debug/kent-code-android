# KENT CODE 0.3 — RED PIXEL · Termux × Shizuku

Нативный Android-агент KENT CODE. Отдельный проект: **LUMI VISION не затрагивается**.

## Что работает

- Чёрно-красный интерфейс: **CHAT / FILES / BRIDGE / CTRL**.
- Онлайн AI-FLEX: выбор модели, собственный API-ключ (Android Keystore), 1–500 шагов.
- Работа с UTF-8 файлами изолированной рабочей папки; TRUSTED MODE для файлов — отдельно.
- Обычный `run_command` от UID приложения Android (по подтверждению).
- **Новый KENT BRIDGE (по умолчанию выключен):**
  - `run_termux` — команда в настоящем Termux: Python, Git, Node.js, если установлены пакеты.
  - `run_adb` — через установленный в Termux `rish` + запущенный Shizuku; Android `uid=2000(shell)`, **не root**.
  - Android-права и состояние Shizuku проверяются отдельными тестовыми кнопками в BRIDGE.
  - Каждая предложенная ИИ команда показывается полностью и требует **отдельного одобрения**. TRUSTED MODE не распространяется на команды.
- Фоновый запрос к Termux через официальный `RUN_COMMAND` intent, возврат stdout/stderr/exit code через одноразовый `PendingIntent`; ожидание ответа до 120 секунд.

## Подключение на Vivo X200

Условия: Termux с пакетом `com.termux` (>= 0.109), Shizuku запущен через ADB, а файлы `~/rish` и `~/rish_shizuku.dex` уже проверены командой `~/rish -c 'id'`.

В **Termux** выполни:

```bash
mkdir -p ~/.termux
# Включить разрешение RUN_COMMAND для внешних приложений (запись в настройках Termux).
printf '\nallow-external-apps=true\n' >> ~/.termux/termux.properties
termux-reload-settings
```

Установи **экспериментальный debug APK** из Actions/Release. Debug ID приложения: `ai.kent.code.red`, чтобы не перезаписывать раннюю KENT CODE 0.1. На GitHub Actions ключи не хранятся.

В приложении открой **BRIDGE**:
1. Нажми «Выдать KENT разрешение Termux». Если системного запроса нет — открой **Настройки Android → Приложения → KENT CODE RED → Разрешения → Дополнительные разрешения → Run commands in Termux environment** и разреши.
2. Убедись, что параметр `allow-external-apps=true` сохранён в `~/.termux/termux.properties`.
3. Включи BRIDGE с отдельным подтверждением.
4. Запусти «Тест Termux: id» и «Тест Shizuku: id». Второй должен выдать `uid=2000(shell)`.
5. В CHAT попробуй: «Проверь Python в Termux командой python --version» или «Покажи список установленных сторонних приложений через Shizuku». Прежде чем одобрять команды, **прочитай их полностью**.

Если Android блокирует запуск Termux — открой Termux на экране и разреши ему фоновую работу. После перезагрузки устройства Shizuku (если запущен по ADB) обычно требует повторного запуска.

## Границы безопасности

- **Не root**; UID Shizuku shell не даёт доступ ко всему телефону.
- BRIDGE выключен по умолчанию, дополнительно нужен системный `RUN_COMMAND` permission и включение `allow-external-apps` внутри Termux.
- На каждый shell-вызов обязательно **отдельное согласие**. Агента не следует использовать для бесконтрольного исполнения команд или работы с личными ключами.
- Команды Termux могут читать данные пользователя Termux: SSH/Git токены, файлы и данные приложений, доступные этому UID. Разрешай только понятные команды; сведения из stdout/stderr передаются внешнему серверу AI-FLEX при следующем обращении модели.
- Таймаут или кнопка остановки прекращают **ожидание в KENT CODE**, но не обязательно уже выполняемую команду Termux. Долгие процессы нужно завершать отдельно в Termux.
- AI-FLEX работает онлайн; серверные ошибки 503/524 остаются возможными. Запись файлов ограничена объёмом 250 KB.
- Привилегии другого приложения/системного раздела не предоставляются автоматически. Нет автоматической синхронизации GitHub из Android APK, API-ключ не публикуется в репозитории.

## Сборка

Java 17, Gradle 8.13, Android Gradle Plugin 8.13.2, SDK 35, min SDK 26. Зависимостей от Shizuku SDK **нет**: мост использует установленный `rish` из Termux. CI проверяет JVM smoke-tests и запускает `gradle :app:assembleDebug`. На main workflow публикует APK как pre-release GitHub Releases (в Actions artifact у аккаунта исчерпана квота). Debug-APK может менять подпись между CI-запусками; переустановка может потребовать удаления экспериментального debug-приложения **с потерей его локальных данных**.

### Проверка после сборки

1. Приложение стартует, вкладка BRIDGE открывается.
2. Termux возвращает `exitCode=0` и свой UID, Shizuku — `uid=2000(shell)`.
3. Команда из чата не запускается без отдельного подтверждения, даже в TRUSTED MODE.
4. При выключенном BRIDGE инструмент возвращает отказ без выполнения.
5. Если отключить Shizuku, `run_adb` должен сообщать об ошибке, а `run_termux` может продолжать работать.

Тестов на реальном Vivo X200 нет до установки свежего APK и ручной проверки.
