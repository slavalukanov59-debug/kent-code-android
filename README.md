# KENT CODE 0.9

Нативная среда Android для задач разработки на русском языке. Разделы приложения — **Чат**, **Задачи**, **Действия**, **GitHub** и **Настройки**.

- **Чат** отправляет задачу выбранному провайдеру. Остаток AI-FLEX берётся из документированного API. При недоступности данных отображается «Баланс: неизвестно».
- **Задачи** сохраняет цель, ход работы, журнал, изменения файлов и доступный расход. После остановки задачу можно продолжить с её локальными контрольными точками.
- **Действия** открывает рабочие файлы, Termux, память и KENT LAB. При включённом AUTOPILOT автоматические записи действуют только в частной рабочей папке на первом запуске задачи. Удаление, правки после возобновления и изменения в LAB требуют подтверждения.
- **GitHub** читает файлы, дерево, коммиты, diff и Actions. Текстовый файл можно сохранить в рабочей папке и затем загрузить из неё в редактор коммита. Ветки, коммиты и черновики PR создаются через просмотр операции и подтверждение. Для записи используйте токен репозитория с соответствующими правами.
- **Настройки** хранят отдельные зашифрованные ключи провайдеров. Текст, который агент читает в выбранной рабочей папке, может входить в запрос к этому провайдеру.

## Режим разработчика

В **Чате** включите **Режим разработчика**. Начните с новой задачи или откройте проект через **Проекты**. Для новой разработки агент создаёт папку в существующей рабочей области, пишет файлы и сверяет результат через инструменты. План, текущий этап, результаты и контрольные точки доступны в **Задачах**. История действий и изменения доступны в **Действия → Журнал**. После перезапуска откройте задачу и подтвердите продолжение.

Для работы с GitHub укажите `владелец/репозиторий` или полный адрес и исходную ветку. Публичные файлы доступны для чтения без токена. Для приватного репозитория, поиска кода и отправки изменений сохраните токен в разделе **GitHub**. Дайте токену права на содержимое выбранного репозитория и на создание PR при необходимости. Агент может прочитать структуру, исходники, коммиты, diff и состояние Actions. Перед созданием ветки, отправкой коммита и открытием черновика PR приложение показывает операцию и запрашивает отдельное подтверждение. Успешная отправка возвращает ссылку GitHub.

В **Проектах** доступны просмотр исходников с подсветкой, экспорт, корзина и импорт. Для ZIP используйте системный выбор документа, просмотрите содержимое и выберите папку. При восстановлении проверенного бэкапа вставьте сохранённый SHA-256. Для GitHub-импорта выберите репозиторий и ветку. Приложение импортирует файлы из одного снимка коммита, пропускает служебные записи, ссылки и крупные бинарные файлы. Подтверждённая замена сохраняет прежнюю папку в корзине. Через **Анализ** можно открыть диалог с выбранным проектом.

Агент готовит ZIP инструментом `project_export`. Нажмите **Сохранить подготовленный ZIP** в чате и выберите место в системном окне. Окончательный результат появляется после записи и проверки документа.

## Экспорт ZIP

Откройте **Действия → Файлы**, перейдите в рабочую папку и нажмите **Экспорт ZIP**. После подготовки архива Android предложит выбрать место сохранения. KENT CODE проверит записанный ZIP и покажет количество файлов, размер и SHA-256. Служебные файлы, известные приложению ключи и символические ссылки исключаются. Исходные файлы остаются в рабочей папке.

## Termux

KENT CODE сначала проверяет локальный мост на `127.0.0.1:47883` и использует уже работающий сервер после аутентификации. Если подключение отклонено, приложение может запустить Python-помощник через официальный `RUN_COMMAND` с параметром фонового выполнения после разового подтверждения или по сохранённому разрешению. Экран Termux при таком запуске не открывается. Android может показать уведомление службы Termux. [Официальное описание RUN_COMMAND](https://github.com/termux/termux-app/wiki/RUN_COMMAND-Intent)

### Настройка один раз

1. Откройте **Действия → Termux → Настроить Termux** и скопируйте команду установки в Termux. При обновлении сначала завершите вручную запущенный предыдущий помощник через Ctrl+C в его сессии. Если исходники 0.9 уже скачаны, установите Python командой `pkg install python` и выполните следующие команды из каталога исходников. [Помощник Termux 0.9](https://raw.githubusercontent.com/slavalukanov59-debug/kent-code-android/0811a4e815ac6d9aec726bba5703971979fb3556/tools/kent_bridge_server.py)

   ```sh
   install -d -m 700 "$HOME/.kent-bridge"
   install -m 700 tools/kent_bridge_server.py "$HOME/.kent-bridge/server.py"
   ```

2. Если токен ещё не создан, один раз запустите `python "$HOME/.kent-bridge/server.py"`. Прочитайте локальный файл `~/.kent-bridge/token` в Termux и вставьте его значение в поле **Токен локального моста**. Существующий токен можно использовать повторно. Помощник хранит файл в частной папке Termux, а KENT CODE сохраняет введённое значение в зашифрованном хранилище. Команда запуска содержит путь к скрипту. Включите мост в **Действия → Termux**.
3. Для фонового запуска добавьте `allow-external-apps=true` в `~/.termux/termux.properties` или измените существующий параметр и выполните `termux-reload-settings`. Нажмите **Выдать RUN_COMMAND**. На некоторых устройствах разрешение находится в **Настройки → Приложения → KENT CODE RED → Разрешения → Дополнительные разрешения → Run commands in Termux environment**.
4. Нажмите **Подключить** и подтвердите разовый запуск при необходимости. Пункт **Разрешить фоновый запуск моста** сохраняет разрешение для следующих запусков, пока KENT CODE открыт. Кнопка **Проверить** только считывает состояние подключения.

### Когда установленный Termux не поддерживает RUN_COMMAND

Поддержка определяется установленной сборкой и разрешениями Android. В проверенной ветке исходников Google Play API внешнего `RUN_COMMAND` отсутствует. Если в приложении отображается отсутствие API или запрет запуска, запустите `python "$HOME/.kent-bridge/server.py"` в Termux и нажмите **Домой**. Пока помощник работает, KENT CODE подключается к нему по уже сохранённому токену. Android и настройки энергопотребления Vivo могут остановить фоновый процесс. При остановке запустите помощник снова. [Ограничения Android на фоновое выполнение](https://developer.android.com/about/versions/oreo/background) · [Манифест ветки Google Play](https://github.com/termux-play-store/termux-apps/blob/fea9fe2cfc484c621e5bf7e42875dab3277b8f90/termux-app/src/main/AndroidManifest.xml)

После подтверждения проверки агент передаёт временный снимок открытого проекта в Termux. **Действия → Диагностика** показывает статус, stdout, stderr и полученный код выхода. Проверку через локальный мост можно отменить. Для команд через официальный мост отмена прекращает ожидание результата, а время выполнения ограничено таймаутом. При проблемах со входом, таймауте или несовместимом ответе проверьте токен и версию помощника.

### Приёмка на Vivo X200

1. Запишите версию Android, источник установки Termux и значение `TERMUX_VERSION` из `termux-info`. Проверьте наличие пункта **Run commands in Termux environment** у KENT CODE RED. Для варианта без разрешения выполните сценарий локального подключения из предыдущего раздела.
2. Убедитесь, что старый помощник завершён. С выданным разрешением `RUN_COMMAND` нажмите **Подключить** в KENT CODE. Проверьте, что экран остаётся в KENT CODE и статус подтверждает подключение. Затем нажмите **Проверить** и убедитесь, что приложение обнаруживает уже работающего помощника.
3. Запустите и отмените длительную проверку тестового проекта. Проверьте компиляцию с ошибкой и после её исправления. Сверьте фактический статус, вывод и код завершения. Затем заблокируйте и разблокируйте экран и повторите подключение.
4. Отключите запуск по запросу и проверьте состояние при остановленном помощнике. Запустите помощник вручную в Termux, вернитесь через **Домой** и подтвердите подключение. Проверьте, что при неподходящем токене приложение показывает ошибку аутентификации.

### Проверки на устройстве

1. Включите режим разработчика, укажите тестовый репозиторий и попросите найти ошибку и подготовить исправление в отдельной ветке. Сначала отклоните один запрос записи и проверьте состояние репозитория. Затем отдельно подтвердите ветку, коммит и черновик PR. Сверьте возвращённые ссылки и diff с GitHub.
2. Создайте небольшой проект, откройте длинный исходник, переключите вкладку и поверните экран. Проверьте положение списка и чата, доступность поля над клавиатурой и сохранение открытого проекта.
3. Экспортируйте проект, импортируйте тот же ZIP в новую папку с SHA-256, сравните важные файлы. Проверьте отказ при неверной сумме и возможность восстановить предыдущий проект из корзины после подтверждённой замены.
4. Подключите Termux. Запустите компиляцию C++ сначала с синтаксической ошибкой, затем после её исправления. Сверьте коды выхода и вывод. Проверьте отмену и сценарий с отсутствующим компилятором.
5. Приостановите задачу после правки и перезапустите приложение. Сверьте план, журнал, изменённый файл и последнюю операцию. Возобновите задачу по кнопке **Продолжить** и проверьте, что для новых внешних действий снова требуется подтверждение.

## Сборка и установка

JDK 17, Gradle 8.13, Android SDK 35, min SDK 26. Команда проверки и сборки:

```sh
gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

APK, SHA-256 и сведения о сертификате доступны в артефакте запуска **Android APK**. Debug-сборка 0.9 использует прежний ID `ai.kent.code.red` и `versionCode 18`. Обычные сборки GitHub Actions используют временный debug-ключ.

### Безопасное обновление с 0.8 и предыдущих версий

1. В установленной версии экспортируйте важные рабочие папки через **Действия → Файлы → Экспорт ZIP**. Сохраните архивы за пределами данных KENT CODE. Проверьте, что ZIP читается и SHA-256 совпадает со значением, показанным при экспорте. ZIP рабочей папки сохраняет файлы проекта. Ключи, настройки и журнал задач хранятся в данных приложения.
2. Распакуйте артефакт CI и проверьте контрольную сумму. Проверьте ID APK и сертификат фактически установленного приложения с помощью Android SDK Build Tools и ADB.

   ```sh
   sha256sum --check KENT-CODE-debug.apk.sha256
   installed_apk=$(adb shell pm path ai.kent.code.red | tr -d '\r' | sed -n '1s/^package://p')
   test -n "$installed_apk" && adb pull "$installed_apk" installed-kent.apk
   aapt dump badging installed-kent.apk | head -n 1
   aapt dump badging KENT-CODE-debug.apk | head -n 1
   apksigner verify --print-certs installed-kent.apk
   apksigner verify --print-certs KENT-CODE-debug.apk
   ```

3. Установка с сохранением данных возможна при совпадении ID и SHA-256 сертификата подписи и при более высоком `versionCode`. После проверки можно выбрать APK в Android или выполнить `adb install -r KENT-CODE-debug.apk`. При несовпадении оставьте текущую версию установленной и используйте для проверки 0.9 другое устройство или эмулятор. Для обновления этой копии нужен APK с её доверенной подписью.
4. После обновления проверьте доступ к существующим файлам, истории чата, задачам и настройкам. Проверьте восстановление копии проекта в новой папке и сравните её файлы с оригиналом.

Две сборки 0.7 из коммита `b3f2f69` используют разные сертификаты. SHA-256 сертификата сборки №49 — `39859816ac8128107259b2e3d001a2b882bdee3d3ada17ebf34f90f7e07405be`, сборки №50 — `9f5f5f5be2000996fc19ad46f54ea9997374c64b820d86c6470bb80dedd52f04`. Сверяйте сертификат своей установленной копии отдельно. [Релиз №49](https://github.com/slavalukanov59-debug/kent-code-android/releases/tag/kent-build-49) · [Сборка №50](https://github.com/slavalukanov59-debug/kent-code-android/actions/runs/44979594726)

### Постоянный ключ для сборок GitHub Actions

Владелец репозитория добавляет в GitHub Actions Secrets `KENT_ANDROID_KEYSTORE_BASE64`, `KENT_ANDROID_KEY_ALIAS`, `KENT_ANDROID_STORE_PASSWORD`, `KENT_ANDROID_KEY_PASSWORD` и `KENT_ANDROID_CERT_SHA256`. Первый секрет содержит Base64 существующего keystore. Последний задаёт SHA-256 доверенного сертификата, предварительно полученный из установленной сборки или другого проверенного источника.

В ручном запуске **Android APK** выберите проверенную ветку и включите `stable_signing`. Отдельная задача подпишет APK после тестов и сверит сертификат с заданным отпечатком. При несовпадении сборка с постоянной подписью отсутствует. Подписанный APK, его контрольная сумма и сертификат находятся в артефакте `KENT-CODE-stable-debug-*`. Ключ и пароли вводятся через настройки GitHub Secrets.

# KENT CODE 0.5.3 — RED PIXEL · Termux × Shizuku · AI-FLEX / OpenRouter

## 0.4.4 — счётчик токенов и остатка лимита задачи

Во вкладке **CHAT** появилась панель **ТОКЕНЫ ЗАДАЧИ**, показывающая в реальном времени:

- **Использовано / установленный лимит**, **осталось токенов** и визуальная шкала до 100%.
- Отдельно входные/выходные токены, число успешных вызовов API и суммарный расход токенов через KENT для выбранного провайдера (AI-FLEX или OpenRouter).
- Источник и состояние задачи, предупреждение, когда API не возвращает `usage.total_tokens` и используется оценка по длине запроса/ответа.
- Данные сохраняются после каждого успешного API-запроса и отображаются после перезапуска Android-приложения. Если приложение закрыто во время задачи, последняя задача отмечается прерванной.
- Счётчики текущей задачи сбрасываются только при запуске **новой** задачи; суммарный расход KENT для каждого провайдера сохраняется.

**Важно:** **ОСТАЛОСЬ** = установленный в CTRL лимит токенов **одной задачи**, **НЕ** баланс/квота AI-FLEX, **НЕ** оставшееся контекстное окно. У пользователя нет в приложении достоверного API для остатка средств. Даже точное `usage.total_tokens` не заменяет данные биллинга AI-FLEX, особенно при скрытых расходах/кеше. В случае отсутствия usage цифры приблизительные. Лимит проверяется **между** запросами, отдельный запрос может превысить остаток и быть оплачен. Ошибочные/прерванные запросы без usage могут не попасть в счётчик. Сверяй расходы с кабинетом провайдера.

Проверка на устройстве: установи новый APK, в CTRL задай тестовый лимит 30 000, запусти короткую задачу, наблюдай рост после каждого успешного API-ответа, перезапусти приложение и проверь сохранение чисел. Проверь смену AI-FLEX ↔ OpenRouter и отсутствие сброса настроек BRIDGE.

## 0.5.3 — безопасная обработка ошибок AI-FLEX и повторов

После KENT EVOLUTION 0.6 на телефоне были видны сообщения `Ошибка API: timeout` и `HTTP 500: upstream error: do request failed`. Это сбои соединения/прокси, не ошибки синтаксиса Java. В таких ситуациях файлы, созданные через Termux, не стираются автоматически, но работа в рамках текущей миссии помечается ошибкой.

- Для временных HTTP 429/500/502/503/504/529 приложение автоматически **один раз повторяет только API-запрос** после короткой паузы. В журнале видна попытка восстановления. **Инструменты Termux/ADB не выполняются повторно** в ходе такого повтора.
- **Сетевой таймаут НЕ повторяется автоматически**, потому что сервер мог выполнить ответ и уже списать кредиты. Выводится честное предупреждение, что состояние и средства следует проверить перед ручным продолжением.
- Таймаут чтения ответа увеличен с 95 до 120 секунд.
- В JOBS продолжение длинной миссии отправляет сокращённое исходное задание (макс 3600 символов) вместе с контрольной точкой, с явным указанием проверять Git/PROGRESS.md и не повторять действия вслепую. Полный оригинал остаётся в записи миссии (в пределах ограничения сохранения), но не отправляется автоматически при каждом продолжении.
- Убрана устаревшая надпись о лимите токенов при продолжении. Локального бюджетного ограничения **нет**; API-вызовы могут стоить денег, а повтор запроса тоже способен повлиять на оплату.
- Отдельная тестируемая политика повторов (`ApiRetryPolicySmokeTest`), плюс обычная сборка Gradle CI.

**Важно:** это обработка временных сбоев клиента, а не ремонт серверов AI-FLEX/Claude. Если после повторной попытки сервер продолжает отвечать 500, задача корректно останавливается, а пользователю следует проверить фактическое состояние файлов и подождать восстановления провайдера. Исходные файлы и сохранённые точки JOBS не удаляются.

### Рекомендации на устройстве

1. На вкладке JOBS посмотри статус миссии; НЕ запускай заново весь мегапромпт.
2. В Termux сначала проверь реальную папку `~/kent-lab/kent-evolution-06`, Git status и PROGRESS.md.
3. По возможности выключи AUTOPILOT при первой попытке возобновления.
4. Если таймаут повторяется, проверь AI-FLEX в браузере; при необходимости временно выбери другую доступную модель, учитывая расход кредитов.

## 0.5.1 — исправлено перепутанное поле API-ключа

Если пользователь по ошибке вставлял длинный текст задания (например, `KENT EVOLUTION — SELF IMPROVEMENT 0.6`) в поле API-ключа в CTRL, раньше запрос мог завершиться `Unexpected char 0x0a in header value: Bearer ...` и показать фрагмент текста в истории чата. Это происходило до отправки HTTP-запроса, задача не выполнялась.

Исправлено: API-ключ проходит проверку на непустое значение, отсутствие пробелов, Unicode и переносов строк перед **сохранением** и перед **каждым HTTP-запросом**, включая ранее ошибочно сохранённые ключи. Ошибки заголовков Authorization теперь скрываются из журнала. В CTRL поле ключа однострочное и явно подписано «Только API-ключ, НЕ текст задачи». Перед запуском миссии также проверяется, что сохранённое значение выглядит как корректный HTTP-токен (не гарантирует, что ключ действителен у провайдера).

**Как исправить уже возникшую ошибку:** CTRL → AI-FLEX → «Удалить API-ключ выбранного провайдера» → вставить действительный ключ в верхнее поле → «Сохранить настройки». Длинный промпт отправлять через CHAT. Если ошибка уже осталась в старом локальном журнале, экспортируйте его осторожно и не публикуйте личные данные. До исправления 0.5.1 непроверенный текст мог оказаться в ошибке.

**Внимание:** AUTOPILOT и лимит токенов не затронуты. Рекомендуем при самостоятельной разработке выставить 30–40 тысяч токенов, 10–20 API-шагов и на первом этапе выключить AUTOPILOT.

## 0.5.0 — MISSION CONTROL / центр управления задачами

Добавлена вкладка **▤ JOBS** на верхней панели, с локальным надёжным хранением до 25 миссий и их контрольных точек. **Каждая новая задача из CHAT** автоматически создаёт запись:
- Исходная формулировка, выбранный провайдер/модель, статус, число сессий, API-запросов, использованных инструментов и примерное число токенов за всю миссию.
- Этап разработки, краткое описание выполненного и следующего действия, список этапов (**прогресс сообщает модель; это НЕ подтверждение успешного теста**).
- Кнопка **«Приостановить»** запрашивает отмену перед следующим шагом; уже запущенные команды Termux/ADB могут продолжить работу.
- **«Продолжить миссию»** после остановки, лимита токенов, API-ошибки или перезапуска Android — **только после ручного подтверждения**. Кент запускает новую модельную сессию и должен сначала перечитать фактическое состояние файлов, Git status и PROGRESS.md. Прежний контекст ИИ не восстанавливается автоматически, и возможны ошибки при повторном выполнении команд.
- Выбор любой сохранённой миссии из списка и экспорт **локального отчёта TXT**. В чат-журнале остаются полные ответы (в пределах ротации журнала).
- Встроенный tool \`mission_checkpoint\` позволяет агенту записывать структурированный план (этап, проверенные наблюдения, следующий шаг, completed/total) и обновлять его после тестов. За запись не требуется разрешение Termux — это внутренний приватный файл приложения.
- Журнал миссий сохраняется с \`AtomicFile\` в приватном пространстве приложения, отдельно от чата; при смерти процесса оставшиеся миссии помечаются **«прервана Android»**, а не возобновляются автоматически.
- Состояние выполняемой задачи отделено от того, какую историческую миссию пользователь просматривает, чтобы действия не записывались в чужую запись.

**Ограничения:** это не полноценный фоновый планировщик; после убийства приложения или перезапуска телефон сам не продолжит выполнение. Модель может проигнорировать \`mission_checkpoint\` или написать неверный отчёт: проверяй реальный Git diff и тесты. Данные прошлых задач 0.4.x не восстанавливаются задним числом. Лимит токенов в CTRL работает на **каждую новую сессию**; при продолжении лимит сбрасывается, а накопленный расход по миссии суммируется. Проверяй фактическую оплату в AI-FLEX. Если предыдущие процессы Termux ещё работают, перед нажатием «Продолжить» дождись их завершения и убедись в состоянии проекта.

### Ручной тест на Vivo X200

1. Отправь небольшую задачу через CHAT, затем открой JOBS — должна появиться запись «выполняется» с ID.
2. Попроси модель составить план и использовать \`mission_checkpoint\`, проверь заполнение этапов и счётчиков.
3. Останови задачу, проверь «остановлена» и экспорт отчёта.
4. Закрой и перезапусти приложение, убедись в сохранении списка и отметок.
5. Нажми «Продолжить» и проверь, что Кент сначала читает файлы/Git и не удаляет ничего автоматически.
6. Во время выполнения переключись на просмотр другой сохранённой миссии, проверь, что счётчики и чекпоинты остаются у активной задачи.

## 0.4.2: восстановление журнала и защита от runaway-контекста

Симптом: во время попытки самообновления агент потратил около **6 млн токенов по счётчику пользователя**, после чего чат сбросился, и финальный отчёт исчез. Подтверждённые исходным кодом ошибки версии 0.4.1:

- Пользовательские сообщения хранились только в `MainActivity.messages` в оперативной памяти, а API-контекст только в `KentAgent.history`. После убийства процесса Android обе истории исчезали.
- `KentAgent.request()` отправлял **весь** список `history` на каждом API-шаге; порог 54 сообщения лишь предупреждал пользователя, ничего не сокращая. Многошаговый агент мог потреблять огромный объём входных токенов.
- Лимит API-шагов не ограничивал *суммарные токены* и расходы на запросы.

Исправлено:
- Полный журнал сообщений и результатов инструментов записывается после каждого события в приватный `JSONL` (2 ротационных сегмента до 5 MB каждый). При следующем запуске показываются последние 120 записей; кнопка **«⇩ Журнал»** экспортирует сохранённый JSONL в выбранный пользователем файл. В UI держатся только последние 120 карточек, чтобы не раздувать память. Журнал **не переносит живой модельный контекст через перезапуск** — после сбоя нужно попросить ИИ проверить файлы/PROGRESS.md. Старые события из 0.4.1 невозможно восстановить, если они не записывались на диск.
- Модель получает текущую задачу и **недавние полные группы вызовов tools**, чтобы исключить «осиротевшие» tool replies. Размер удерживаемой истории ориентировочно 32k символов, вывод каждого инструмента максимум 5k символов. Это не точный токенизатор и не гарантия сохранения всех деталей: для длительной разработки агенту предложено вести `PROGRESS.md`.
- В CTRL появился ограничитель **токенов на одну задачу** (по умолчанию 80 000, настройка 10 000–300 000). Считаем `usage.total_tokens`, если API отдаёт его; иначе приблизительно оцениваем по длине данных. Это предупредительная оценка, **не жёсткий биллинговый предел**; одно обращение может превысить оставшийся бюджет.
- Токены тратятся за каждый запрос, поэтому для первых тестов устанавливай 10–20 API-шагов, токеновый лимит 30–80k. После больших заданий используйте отдельные короткие итерации.

## Новое в 0.4.0: прямой OpenRouter

На вкладке **CTRL → ИИ-провайдер** выбери **OpenRouter** вместо AI-FLEX. Сохранённые ключи AI-FLEX не отправляются в OpenRouter: ключи шифруются и хранятся **раздельно** в Android Keystore. В модели укажи точный OpenRouter ID, например:

- `anthropic/claude-sonnet-5.5` — качественный повседневный код, поддерживает tool calling.
- `anthropic/claude-opus-5.5` — сложные многошаговые задачи; обычно дороже.

## Резервное копирование проектов Termux

Для сборки `googleplay.2026.10.09` применяйте сценарий ручного запуска локального моста из раздела Termux 0.9 выше. У Termux и его плагинов разных источников разные подписи. Для установки обновления используйте APK из того же источника. [Документация Termux](https://github.com/termux/termux-app#installation)

Чтобы сохранить рабочий проект (не весь набор токенов), открой старый Termux и выполни:

```bash
termux-setup-storage
cd ~
git -C KENT-CODE-Android status --short
tar -czf ~/storage/downloads/KENT-CODE-Android-safe-backup.tar.gz \
  --exclude='.git' --exclude='.env' --exclude='*.pem' --exclude='*.key' \
  -C "$HOME" KENT-CODE-Android
tar -tzf ~/storage/downloads/KENT-CODE-Android-safe-backup.tar.gz | head -30
ls -lh ~/storage/downloads/KENT-CODE-Android-safe-backup.tar.gz
```

Если есть другие личные проекты, архивируй их **отдельно**. Этот архив не является полной резервной копией всех данных Termux. Проверь, что там нет секретов. Сделай дополнительную копию на ПК/USB, а не полагайся на единственный архив. Не восстанавливай старый `$PREFIX/usr` из Google Play сборки в новую F-Droid.

Проверенный архив можно восстановить в Termux на отдельном устройстве. Устанавливай все плагины для этого Termux из того же источника.

```bash
termux-setup-storage
pkg update && pkg upgrade -y
pkg install git python nodejs openssh curl -y
cd ~
tar -xzf ~/storage/downloads/KENT-CODE-Android-safe-backup.tar.gz
cd ~/KENT-CODE-Android
git init
git remote add origin https://github.com/slavalukanov59-debug/kent-code-android.git
# При необходимости: настрой gh auth login для доступа к приватному репозиторию.
```

Файлы `rish` и `rish_shizuku.dex` можно повторно экспортировать из Shizuku. После копирования в домашнюю папку используй `chmod 700 ~/rish` и `chmod 400 ~/rish_shizuku.dex`. На другом устройстве авторизацию Shizuku нужно подтвердить заново.

Для настройки моста на другом устройстве воспользуйся инструкцией 0.9 в разделе **Termux**.

## Версия 0.4.1 — AUTOPILOT / без подтверждений инструментов

В **CTRL** включи **«⚡ AUTOPILOT — БЕЗ ОКОН ПОДТВЕРЖДЕНИЯ»** и нажми **«Сохранить настройки»**. Функция выключена по умолчанию. Когда она включена, **все** предлагаемые ИИ инструменты (`run_termux`, `run_adb`, `run_command`, работа с файлами) выполняются **без отдельного окна**. Запросы команд появляются в чате с отметкой **⚡ AUTO** (первые 700 символов), сверху отображается индикатор. Кнопка **«Стоп»** останавливает дальнейшие действия, но уже запущенные процессы могут продолжить работу. Отключается в CTRL; переключатель сохраняет значение между запусками.

**Риски:** ИИ может ошибиться, удалить или изменить важные файлы, выполнить команду с правами Termux или Shizuku/ADB либо прочитать приватные данные. Часть вывода отправляется внешнему ИИ-провайдеру. Используй отдельную рабочую папку и резервные копии; не открывай недоверенные проекты в AUTOPILOT. Это не ROOT и не обход разрешений Android. Собственные запросы Android могут появляться независимо от KENT CODE.

Если AUTOPILOT выключен, сохраняется поведение 0.4.0: отдельные окна подтверждения каждой команды.

Нативный Android-агент KENT CODE. Отдельный проект: **LUMI VISION не затрагивается**.

## Что работает

- Чёрно-красный интерфейс: **CHAT / FILES / BRIDGE / CTRL**.
- Онлайн AI-FLEX: выбор модели, собственный API-ключ (Android Keystore), 1–500 шагов.
- Работа с UTF-8 файлами изолированной рабочей папки; TRUSTED MODE для файлов — отдельно.
- Обычный `run_command` от UID приложения Android (по подтверждению).
- **Новый KENT BRIDGE (по умолчанию выключен):**
  - `run_termux` — команда в настоящем Termux: Python, Git, Node.js, если установлены пакеты.
  - `run_adb` — через установленный в Termux `rish` + запущенный Shizuku; Android `uid=2000(shell)`, **не root**.
  - Android-права и состояние Shizuku проверяются отдельными тестовыми кнопками в BRIDGE.
  - Каждая предложенная ИИ команда показывается полностью и требует **отдельного одобрения**. TRUSTED MODE не распространяется на команды.
- Фоновый запрос к Termux через официальный `RUN_COMMAND` intent, возврат stdout/stderr/exit code через одноразовый `PendingIntent`; ожидание ответа до 120 секунд.

## Подключение на Vivo X200 с Termux Google Play

На пользовательском Vivo X200 проверена команда `termux-info`: **`TERMUX_VERSION=googleplay.2026.10.09`**. Эта конкретная сборка не регистрирует `com.termux.permission.RUN_COMMAND` (в `dumpsys package com.termux` нет разрешения), поэтому нельзя выдать право через `pm grant` и официальный `RUN_COMMAND` в ней не работает. **Не удаляй Termux: можно потерять рабочие проекты и ключи.**

Добавлен отдельный режим: пользователь вручную запускает защищённый локальный TCP-сервер внутри Termux. KENT CODE подключается исключительно к `127.0.0.1:47883` с 48-символьным токеном. Внешние сетевые интерфейсы не используются, порт наружу не открывай. Каждая команда от AI требует отдельного подтверждения.

В Termux, где уже есть репозиторий:

```sh
cd ~/KENT-CODE-Android
git pull --ff-only
pkg install python -y
python tools/kent_bridge_server.py
```

Терминал покажет `LOCAL TOKEN`. Копируй токен **только в KENT CODE → BRIDGE**, не публикуй его в чатах или репозитории. Токен сохраняется локально в Android Keystore и `~/.kent-bridge/token`. Чтобы остановить мост, нажми Ctrl+C в Termux. Если Termux закрыт или остановлен Android, мост перестанет отвечать.

Установи APK версии 0.3.1. Во вкладке BRIDGE:

1. Найди раздел **Google Play Termux — без RUN_COMMAND** и введи токен с экрана Termux (48 символов).
2. Нажми «Сохранить токен локального моста».
3. Включи BRIDGE с отдельным подтверждением.
4. Проверь «Тест Termux: id» (UID Termux) и «Тест Shizuku: id» (`uid=2000(shell)`). Shizuku должен быть уже запущен и `~/rish -c 'id'` должен работать.
5. КЕНТ получает доступ к инструментам `run_termux` и `run_adb` только после подтверждения каждой команды.

Для Termux из F-Droid / GitHub, где `RUN_COMMAND` зарегистрирован, по-прежнему работает прямой Intent: `allow-external-apps=true`, выдача `RUN_COMMAND` приложению и запуск BRIDGE. Локальный токен имеет приоритет при его наличии; его можно очистить через пустое поле «Сохранить токен».

**Ограничения:** это не root; TCP-токен не заменяет пользовательское подтверждение; команды Termux запускаются с полными правами пользователя Termux, Shizuku даёт только ADB-shell. После каждого выполненного инструмента результат возвращается модели AI-FLEX при следующем запросе, поэтому нельзя запускать команды, которые печатают пароли или секреты. При остановке ожидания сам процесс Termux может продолжить работу.

## Границы безопасности

- **Не root**; UID Shizuku shell не даёт доступ ко всему телефону.
- BRIDGE выключен по умолчанию, дополнительно нужен системный `RUN_COMMAND` permission и включение `allow-external-apps` внутри Termux.
- На каждый shell-вызов обязательно **отдельное согласие**. Агента не следует использовать для бесконтрольного исполнения команд или работы с личными ключами.
- Команды Termux могут читать данные пользователя Termux: SSH/Git токены, файлы и данные приложений, доступные этому UID. Разрешай только понятные команды; сведения из stdout/stderr передаются внешнему серверу AI-FLEX при следующем обращении модели.
- Таймаут или кнопка остановки прекращают **ожидание в KENT CODE**, но не обязательно уже выполняемую команду Termux. Долгие процессы нужно завершать отдельно в Termux.
- AI-FLEX работает онлайн; серверные ошибки 503/524 остаются возможными. Запись файлов ограничена объёмом 250 KB.
- Привилегии другого приложения/системного раздела не предоставляются автоматически. Нет автоматической синхронизации GitHub из Android APK, API-ключ не публикуется в репозитории.

## Сборка

Java 17, Gradle 8.13, Android Gradle Plugin 8.13.2, SDK 35, min SDK 26. Мост Shizuku использует установленный `rish` из Termux. CI проверяет JVM smoke-тесты и запускает `gradle :app:assembleDebug`. На main workflow публикует APK как pre-release GitHub Releases. Для проверки совместимости следуйте актуальной инструкции по безопасному обновлению выше.

### Проверка после сборки

1. Приложение стартует, вкладка BRIDGE открывается.
2. Termux возвращает `exitCode=0` и свой UID, Shizuku — `uid=2000(shell)`.
3. Команда из чата не запускается без отдельного подтверждения, даже в TRUSTED MODE.
4. При выключенном BRIDGE инструмент возвращает отказ без выполнения.
5. Если отключить Shizuku, `run_adb` должен сообщать об ошибке, а `run_termux` может продолжать работать.

Тестов на реальном Vivo X200 нет до установки свежего APK и ручной проверки.
