# Аудит архитектуры Kent Code 0.7

База `feature/kent-0.7-zip-export` сверена с GitHub на `b3f2f69305220cf634ac791bd968961991b5a968`. Аудит выполнен по этой версии перед изменениями 0.8. [Исходный коммит](https://github.com/slavalukanov59-debug/kent-code-android/commit/b3f2f69305220cf634ac791bd968961991b5a968)

| Компонент | Поток данных / управления в 0.7 | Ограничения и риски |
| --- | --- | --- |
| Задачи и модель | `MainActivity` обращается к `KentLocalData`, создаёт запись в `MissionStore` и запускает `KentAgent`. Агент вызывает Chat Completions AI Flex или OpenRouter. `TokenMeter`, `ProviderUsage` и `CreditBalance` учитывают доступные данные провайдера. | Агенту доступны локальные операции и модельные контрольные точки. Идентичность пакета вызовов сама по себе не доказывает отсутствие прогресса. Итог модели мог завершить задачу без результата нужного инструмента. |
| Сохранение | `MissionStore` сохраняет цель, локальные изменения, сводку, учёт и события в `kent_missions.json`. Запись атомарна. При восстановлении незавершённая операция с побочным эффектом требует сверки, возобновление запускает пользователь. `ChatJournal` ведёт ротацию локального JSONL. | При возобновлении цель обрезается, журнал чтений хранит преимущественно счётчики. Статус этапа и прогресс определяет модель. План, активный проект и доказательства диагностического этапа не выделены. |
| Файлы | `SafeWorkspace` работает с `files/workspace`, отклоняет выход из корня и проверяет версии файлов перед записью. `LabWorkspace` хранит отдельные копии исходников приложения в `files/kent-lab`. | Перечисление и чтение ограничены константами, пагинации нет. Между проверкой пути и отдельными файловыми операциями возможна подмена цели со стороны процесса с доступом к рабочей папке. Для резервных копий применяется более строгий дескрипторный обход. |
| ZIP и SAF | `WorkspaceZipExporter` фильтрует защищённые пути и значения ключей, проверяет подготовленный ZIP и считает SHA-256. `WorkspaceExportSession` и `WorkspaceZipDestination` передают файл системному провайдеру документов и читают его обратно. | Импорт существующего ZIP отсутствует. Импорт из `MainActivity` принимает отдельный UTF-8 файл в `imports/`. |
| GitHub | `GitHubPanel` получает токен из `SecureKeyStore`, читает дерево, файл, историю, сравнение и Actions через `GitHubClient`. Ручные операции имеют предварительный просмотр. Коммит одного файла проверяет ожидаемый SHA через GraphQL. | У агента нет доступа к этим операциям. Нет пакетного коммита, постраничного чтения, списка доступных репозиториев и поиска кода. Защита прямого коммита на ветку по умолчанию не покрывает `main`, если в репозитории другая ветка по умолчанию. |
| Termux | `MainActivity` после ручного подтверждения работает с официальным `RUN_COMMAND` через `TermuxBridge` или с аутентифицированным локальным сервером через `LocalTermuxBridge`. `CommandResult` хранит код выхода и сведения о транспортной ошибке. | Остановка ожидания ответа не останавливает процесс в Termux. Таймаут сервера завершает группу локального процесса. Приватные файлы Android недоступны из отдельного приложения Termux. Ручные shell и Shizuku нельзя подключать к агенту как универсальный исполнитель. |
| Интерфейс | RED PIXEL на обычных Android Views. `ChatTimeline` закрепляет позицию чтения, окно учитывает IME и системные панели. Журнал инструментов строится по событиям задачи. | Нет менеджера проектов, подсветки исходников и журнала диагностических запусков. Рабочий каталог и позиции отдельных списков восстанавливаются частично. |
| Данные и сборка | Приватные файлы и Android Keystore привязаны к установке. Debug APK использует `ai.kent.code.red`, release — `ai.kent.code`. GitHub Actions выполняет Java smoke, Python bridge, Android unit, lint и assemble, вычисляет SHA-256. | Сборка debug на чистом раннере создаёт временный сертификат. Совместимость обновления зависит от соотношения отпечатков конкретного установленного APK и новой сборки. Android backup отключён, проектам нужен явный экспорт и проверяемый импорт. |

Интеграция 0.8 использует существующие `GitHubClient`, `SafeWorkspace`, `MissionStore` и ZIP-экспорт. Новые команды Termux используют отдельный протокол выполнения в подготовленной копии проекта и журналируют фактический исход. Версию формата и содержимое пользовательского каталога `files/workspace` следует сохранять при любом обновлении приложения.
